# 000 原则

dsh-superagent 是一个框架，也是一种和智能体共事的方式。它的核心原则是：

**尽可能少占用人的注意力，尽可能多给出价值。**

项目的每一部分，都按它耗费的注意力来衡量。一条消息、一条通知、一个问题、一项设置、面板上的一个元素、文档里的一段话，都在花某人的注意力。花出去的注意力必须换回更多价值，否则就拿掉。

## 对智能体的要求

- **只在被人要求时行动，或在一条写成文字的规则允许时行动。** 一次请求要算数，必须直接对着智能体说，并且来自团队允许的人：在允许名单上，或处在团队开放给请求的那场对话里。没有人要求的工作，需要团队自己写下的规则，并且先以只记录、不动手的方式开始。
- **只在必须有人行动、或有人用得上结果时才开口。** 接到请求时确认一次，并说清自己要做什么。做事的过程中保持安静。结果可以交出来、需要人做决定、或者做不完的时候，再写一次。消息要短，发回提出请求的那场对话。
- **一次只问一个具体问题，** 并且用结构化的形式，让问题送到人那里，而不是埋在一篇长报告里。
- **按影响停，不按力气停。** 局部改动做到可以评审的结果为止。需要设计决定的改动，停在一个清楚的问题上。
- **如实报告。** 草稿标成未完成，失败就说失败，绝不为了不问人而绕过限制。

## 对设计的要求

- **概念要少。** 设计里只有领域概念，例如来源，以及它们的具体实现，例如 GitHub 和飞书。一项业务需要，要么成为其中一个概念的属性，要么成为智能体遵循的一段提示词。不为它再发明一个概念。
- **设置要少。** 一个值几乎适合所有团队时，用默认值代替一项设置。团队用话说出来的行为是提示词，不是设置。
- **面板只展示需要人的东西。** 它先列出等着人的事项。健康的状态不占地方。
- **文档按顺序读。** 每一篇编号文档只建立在它前面的篇章上，读者不会碰到还没介绍过的概念。

## 责任

智能体用你们团队每天都看得到的账号评论、开拉取请求、给人发消息。它发出的每条消息都在花同事的注意力，你要为此负责。智能体能做的越多，操作者对团队越要小心：

- **从窄处开始。** 先用一份短的允许名单，主动发起的工作只记录、不执行。等智能体本来会做的那些事看起来是对的，再把两者放宽。
- **往更安静里调。** 智能体吵的时候，把提示词写得更短、更严，或者先停掉它。不要再加消息去解释这些噪音。
- **不要用它来堆数量。** 大批拉取请求、广播消息和忙活，花掉团队的比给出的多。
- **为它说的话负责。** 读它以你的名义发出的内容，说错了就在提示词里改正。

目标是在该帮忙的时候帮上，其余时间什么都不做。
