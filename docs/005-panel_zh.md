# 005 面板

在 DeepSeek Harness 网页侧栏里打开 **Superagent**，用来监督智能体。面板先排需要人的工作，再排系统健康和历史。这份文档建立在 [000 原则](000-philosophy_zh.md) 到 [004 提示词](004-prompts_zh.md) 之上。

## 三个问题

打开面板，按这个顺序回答三个问题：

1. 现在有没有事需要我？
2. 系统健康吗，做的是对的事吗？
3. 一件工作的历史是什么，从触发经过评估到工单？

## 标签页

标签页跟着工作流走：**总览**、**来源**、**触发**、**评估**、**执行**和**设置**。仓库和账号的安装还没成功之前，总览显示缺什么，并链到相关的设置。

| 标签页 | 显示 |
| --- | --- |
| 总览 | 需要处理的工单、系统问题、最近 24 小时的活动计数，以及执行器负载。每一块都链到它的详细页 |
| 来源 | 来源状态、安装问题和不为零的计数。被滤掉的触发和被丢弃的消息，覆盖的 24 小时窗口和总览相同 |
| 触发 | 线程可按已订阅、评估中、24 小时内的新触发或全部线程来筛。每条线程把触发按最新在前显示，还有决定和订阅 |
| 评估 | 决定，连同它们的理由和匹配到的规则 |
| 执行 | 执行器状态、暂停处理，以及按开放、待启动、工作中、等待触发或已结束来筛的工单。工单详情显示动作、授权、等待中的输入、订阅和派工 |
| 设置 | 来源、评估、执行、提示词和部署。每一组都带自己的保存历史 |

### 读单条记录

一条被丢弃的消息链到它的工单；没有工单时链到它的线程。来源页说明是它的对话消失了，还是来源不再听它。

一条仍由执行器持有的人的后续，标成 **已送到工单**，没有评估。线程上也显示交还的理由，以及仅作上下文的订阅。**再次评估** 可以把那条后续送去评估，或重试一条没有有效判断的触发：被来源滤掉的、一次未完成的评估，或一条既没有非停止决定、也没有执行器确认收到的已送达消息。

工单详情显示最初的触发、决定和理由、范围和策略版本。派工和次要细节折在眼前的动作下面。**重试** 用于输入送达失败，或在受阻或失败的报告之后等人的工单。已结束的工单显示结果，例如 **拉取请求已合并** 或 **被人停止**。

## 设置分组

- **来源：** 每个来源一张卡片，带它的开关、字段和已核对的账号事实。GitHub 还提供接收全部的开关，针对新议题、拉取请求、评论和默认分支的持续集成。轮询和读取限制在高级之下。
- **评估：** 策略版本和规则，然后是 **在每个来源上** 和评估设置。每个来源标签含它的允许名单、成员同步、准入表和机器人名单。同步在启动时跑，也在 **立即同步** 时跑。准入表区分接收范围、发送者是否为成员，以及消息是否对着智能体。评估设置选择接单模式、超时和研判模型。
- **执行：** 工作者模型、并发、目录根、准备命令和被禁止的命令。点一个可用变量，就把它插入准备命令。
- **提示词：** **编辑** 改团队段落、内置部分和技能。**完整提示词** 显示组装后的文本，并和已保存的文本或默认比较。**历史** 列出版本。改过的内置部分标成已更改，可以重置；模板列出它们必须有的占位符。

  一次升级若改变了被覆盖的默认，就把它标成 **默认内容已更新**。面板在团队文本上方比较旧的和新的默认。若旧的默认没有记下，就改为拿团队文本和新的默认比较。选择 **保留我的文本** 或 **采用新的默认**。已移除部分的覆盖列在标签栏下方，下一次保存时丢掉。
- **部署：** 启动问题，带 **再次检查**、状态目录和机器限制。保存的限制不重启就生效。DeepSeek Harness 的插件管理器露出同一页。

## 搜索

页眉搜索按文本、标识、飞书消息标识或一条存下的链接找触发，例如一条 GitHub 评论地址。原消息里没有的飞书链接，要等宿主在当前进程的生存期内读过它，才搜得到。

搜索也按 `#12` 或一条 GitHub 地址这类引用找线程，并按标题或一条匹配的线程找工单。

## 原则

1. **盯住要紧的。** 每个元素回答三个问题之一，否则就拿掉。一个数字只有在它改变监督者要做的事时才出现。
2. **定义要精确。** 类别有可以核对的定义，互斥，并且覆盖每一种情况，工单阶段就是这样。一个标签说出这一行在等谁、需要什么，而不是一个内部状态码。
3. **一个概念一个地方。** 来源状态属于来源；线程和触发属于触发；决定属于评估；工单属于执行。设置按它们所配置的概念分组。总览概括这些页并链过去，自己不变成另一个详细视图。
4. **领域结构。** 面板使用领域术语。内部标识只出现在折起的细节里，名字能解析出来的地方用名字代替标识。
5. **状态要诚实。** 一个计数等于它所链到的列表的长度，没有任何状态和另一件事实矛盾。
6. **默认安静。** 健康的状态不额外占地方。问题必须能动手处理；一次性的网络错误不够。需要人的行直接给出动作。页面说明保持一句，进一步的细节放进（?）提示。破坏性动作需要确认。
7. **控件一致。** 使用 DeepSeek Harness 的设计记号和控件行为。同样的信息在整个面板里看起来应当一样。每个设置块有一条保存栏，只在有改动、保存正在跑或保存失败时可见。
